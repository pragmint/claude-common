# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Purpose

This is a meta-configuration repository containing reusable Claude Code commands, agents, and skills. Components are designed to be copied into other projects — there is no application code, build system, or test suite here.

## Structure

```
agents/       # Specialized subagent definitions
commands/     # Slash command definitions (Markdown with YAML frontmatter)
planning/     # Gitignored directory for plan documents generated by /plan
skills/
└── pragmint/ # Skill definitions for use with the skills system
```

## Architecture

### Commands

Each file in `commands/` defines a slash command with YAML frontmatter (`allowed-tools`, `description`) and a Markdown body that instructs Claude on a workflow. Commands compose other commands and agents via the Task tool.

### Agents

Each file in `agents/` defines a specialized subagent with a focused role. The four agents work in concert with the `/orchestrate` command:

- **analyst** — reviews solutions and plans for quality issues before implementation
- **unit-tester** — writes failing tests (TDD red phase)
- **incremental-implementer** — writes minimal code to make failing tests pass (green phase)
- **careful-refactorer** — improves code quality without breaking tests (refactor phase)

### Orchestration Workflow

`/orchestrate` is the top-level command that drives the full TDD cycle:
1. Health check (`/healthy-run`, `/test`)
2. Plan creation (`/plan` + analyst review) → user approval required
3. Branch creation (`/branch`)
4. Per-increment loop: unit-tester → incremental-implementer → careful-refactorer → `/test` + `/build` + `/lint` → `/commit`
5. Final `/healthy-run` verification

### Skills

Skills in `skills/pragmint/` follow the Claude Code skills system format. The `SKILL.md` file defines the skill entry point.

## Contributing Guidelines

Keep all commands and agents general-purpose and project-agnostic. Do not embed project-specific details. When adding a new command, follow the existing frontmatter format with `allowed-tools` and `description` fields.
